# Analysis_BsReport v1-v4

這份文件的目的不是教怎麼執行腳本，而是記錄 `apps/analysis/Analysis_BsReport_v1.py` 到 `v4.py` 這條主線在研究上想追求什麼、每一版解決了什麼問題、還留下了哪些未完成課題。

如果之後要繼續演化這條線，先看這份，再決定是延伸 `v4`、抽模組，還是另開 `v5`。

## Core Question

這條主線從頭到尾在回答同一個問題：

`bs_report` 裡的券商分點行為，能不能被整理成一個足夠穩定的「吃貨事件」訊號，並在後續價格表現上展現可重複的優勢？

拆開來看，核心其實有 4 層：

1. 如何把每天、每券商、每股票的買賣超行為壓縮成可比較的特徵。
2. 如何定義「不是單日雜訊，而是有持續性的主力佈局」。
3. 如何用 OHLC 去驗證這個訊號之後的價格行為，而不只看主觀案例。
4. 如何從單一訊號，進一步變成可調參、可評分、可拿去做 ML 或策略搜索的研究底座。

## Shared Philosophy

雖然 `v1` 到 `v4` 形式不同，但背後有幾個一致的理念：

- 不直接依賴券商名稱的主觀名單，而是盡量從分布型特徵出發。
- 重點不只是淨買超量，而是「集中度」與「持續性」。
- 權證不能被忽略，因為主力意圖可能會先出現在權證，再映射回標的。
- 事件定義必須能橫跨全市場做比較，所以 percentile / bucket 這類相對位置很重要。
- 回測不該只看平均報酬，還要看事件數、bucket 分層、MFE / MAE、風險輪廓。

## v1

### 核心理念

`v1` 的核心假設是：

單一股票上的主力佈局，不應只從正股分點看，還要把同標的相關權證的籌碼意圖也合併進來。當股票面與權證面同時出現集中的淨買超，且這種狀態持續數日，就有可能形成可交易的事件。

### 追求的目標

- 建立第一個完整的 `bs_report + ohlc + warrant mapping` 一體化研究流程。
- 不再只看單日券商異常，而是把資料壓成能跨日期比較的特徵。
- 把事件定義從主觀觀察，變成可批次回測的規則。

### 方法特徵

- 同時考慮正股與權證端的籌碼分布。
- 特徵重點放在：
  - `posnet_total`
  - `hhi_posnet`
  - `top_posnet_ratio`
  - `dyn_k`
- 事件邏輯是：
  - 先做 cross-sectional score / percentile
  - 再要求高分持續 `persist_days`
  - 並對同股施加 `cooldown`

### 這一版真正重要的貢獻

- 首次把「吃貨」概念從直覺，變成特徵工程加事件回測框架。
- 首次建立出後續所有版本都沿用的資料底座：
  - `bs_report parquet`
  - `ohlc`
  - `warrant_list_dedup`
  - `data/_derived/*`

### 限制

- 權證權重 `alpha` 仍帶明顯人工假設。
- 事件定義偏像「連續高分 streak」，比較厚重，也比較不容易即時描述狀態轉折。
- 評估仍以 forward return 為主，對風險輪廓掌握還不夠細。

## v2

### 核心理念

`v2` 的轉向很明確：把問題從「高分事件」改寫成「吃貨狀態的進入點」。

這一版的想法是：

真正重要的可能不是分數本身有多高，而是某檔股票是否進入一個由 `intensity + concentration` 共同定義的吃貨狀態，而且這個狀態在近 `W` 日內達到足夠出現次數，形成第一次有效進場訊號。

### 追求的目標

- 用更可解釋的 state machine 方式取代 `v1` 的相對綜合分數。
- 減少權重設計的主觀性。
- 明確區分：
  - 強度 `Intensity`
  - 集中度 `Concentration`
  - 狀態進入點 `state entry`

### 方法特徵

- 以 rolling percentile 定義：
  - `posnet_total_pct >= I_th`
  - `hhi_posnet_pct >= C_th`
- `state = intensity & concentration`
- `event =` 近 `W` 天內 state 天數第一次跨越門檻 `P_min`
- 仍保留 `cooldown`

### 這一版的研究意義

- 從「分數很高」轉成「狀態成立」。
- 事件定義變得更接近 regime switch，而不是單純高 ranking。
- 這讓訊號更容易被拆解，也更適合做後續參數搜尋。

### 限制

- 雖然 state 概念比較清楚，但分數層次被壓扁了。
- 對賣壓、負向籌碼分布、價格位置沒有明確懲罰。
- 還是偏二元事件，對事件強弱的層次感不足。

## v3

### 核心理念

`v3` 的核心，是把 `v2` 的狀態判斷重新拉回一個連續型的 soft-score 框架，但保留 percentile 的相對比較能力。

也就是說：

不是只問「有沒有進入狀態」，而是問「這檔股票現在的吃貨程度有多強」，再把這個強度在時間上累積，讓事件代表一段籌碼壓力逐步成形，而不是單日跳點。

### 追求的目標

- 把 `v2` 的 state 機制提升成連續強度分數。
- 讓訊號既保有可比較性，又保留強弱層次。
- 引入更完整的 post-event 評估，不只看 forward return，也看 MFE / MAE。

### 方法特徵

- 用 rolling percentile 建出：
  - `posnet_total_pct`
  - `hhi_posnet_pct`
- 再用權重組成：
  - `s_stage1 = wI * intensity + wC * concentration`
- 再做時間累積：
  - `s_stage1_W`
  - `s_stage1_W_pct`
- 事件定義改成：
  - `s_stage1_W_pct` 首次跨越門檻 `th`
  - 並套用 `cooldown`

### 這一版新增的關鍵能力

- `stage1_bucket`
  - 開始能對不同訊號強度分桶比較，不再只看整體均值。
- `MFE / MAE`
  - 開始把「事件後最高能走到哪」與「最糟會先回撤多少」納入。
- `features_with_stage1_soft.parquet` 與 `scored.parquet`
  - 真正形成後續 ML 與策略搜索的標準化輸入表。

### 這一版的研究意義

`v3` 是這條主線真正從「heuristic 事件規則」走向「研究平台」的版本。

後面的：

- `run_tune_stage1_v3.py`
- `run_backtest_stage1.py`
- `run_ml_*`

幾乎都建立在 `v3` 這個資料表與事件結構上。

### 限制

- 分數仍主要看買方側結構。
- 沒有真正把賣壓當成對稱的反訊號。
- 事件仍偏向「吃貨累積」本身，尚未納入價格位置與技術面過熱過頭的過濾。

## v4

### 核心理念

`v4` 的核心不是推翻 `v3`，而是補上 `v3` 缺的風險感知。

這一版承認一件事：

正向籌碼很強，不代表就是好訊號。如果同時存在高賣壓、賣方也高度集中、或價格已經位在布林通道過高區間，那麼事件雖然看起來很強，實際上可能更接近末端擁擠，而不是低風險的吃貨起點。

### 追求的目標

- 讓 `stage1` 從「只看正向壓力」進化成「正向壓力 - 負向風險」。
- 把事件定義從單純強弱，提升到更接近風險調整後訊號。
- 讓後續 ML / strategy search 拿到更有用的 base signal。

### 方法特徵

- 補上賣方側特徵：
  - `negnet_total`
  - `hhi_negnet`
  - `top_negnet_ratio`
  - `dyn_k_neg`
- 在 `stage1` 分數上加入懲罰：
  - `sell_ratio`
  - `hhi_negnet_pct`
  - `dyn_k_penalty`
- 形成：
  - `s_stage1_adj`
  - `s_stage1_adj_W`
  - `s_stage1_adj_W_pct`
- 再加入價格位置條件：
  - `bb_pos`
  - 以 `bb_max` 避免事件發生在布林高位過熱段

### 這一版真正想解決的問題

- 避免把「主力拉高出貨前的擁擠」誤判成吃貨訊號。
- 讓事件更偏向：
  - 買壓強
  - 賣壓相對可控
  - 價格位置還沒有太擁擠

### 研究上的位置

`v4` 比 `v3` 更像「可交付的 baseline」。

原因不是它一定最好，而是它把前面幾版的問題都收斂到了較完整的訊號定義裡：

- 有正向特徵
- 有負向特徵
- 有累積分數
- 有事件門檻
- 有 bucket
- 有 MFE / MAE
- 有價格位置濾網

這也是為什麼目前若要延伸新研究，應優先從 `v4` 出發，而不是回頭直接改 `v1` 或 `v2`。

## Evolution Summary

如果把 `v1 ~ v4` 濃縮成一條演化線，可以這樣看：

- `v1`
  - 目標：先把正股 + 權證籌碼整合成第一個吃貨事件框架。
  - 關鍵字：整合、直覺分數、持續天數。

- `v2`
  - 目標：把事件改寫成更可解釋的吃貨狀態進入點。
  - 關鍵字：state、rolling percentile、進入點。

- `v3`
  - 目標：把 state 再升級成連續 soft-score，形成穩定研究平台。
  - 關鍵字：stage1 soft-score、bucket、MFE/MAE。

- `v4`
  - 目標：把訊號做成風險調整後的版本，避免高位擁擠誤判。
  - 關鍵字：賣壓懲罰、負向特徵、布林位置過濾。

## What This Line Is Actually Pursuing

從研究哲學上講，這條主線真正追求的不是「找最會漲的股票」而已，而是：

找到一個能描述「主力吸貨壓力正在累積，但市場尚未完全反映」的結構化訊號。

這個訊號理想上要同時滿足：

- 不是單日雜訊
- 不是單一券商名字故事
- 不是單純追價
- 可以跨股票比較
- 可以做事件回測
- 可以提供給 ML 排名或交易規則搜索

換句話說，`Analysis_BsReport_v1~v4` 的長期目標，是把 `bs_report` 從原始交易明細，轉成一個可持續迭代的 alpha research substrate。

## Open Questions

這條線雖然已經走到 `v4`，但還有幾個自然的下一步：

1. `v4` 的賣壓懲罰是否已經過度手工設計。
2. 權證資訊目前主要用在標的映射，是否還有更直接的權證活動特徵可加。
3. `bb_pos` 這種價格位置濾網是否應該抽象成更一般的 regime filter。
4. `stage1` 是否應該拆成更清楚的子訊號，而不是在同一分數裡混合太多效果。
5. 是否應該正式停止維護 `v1` / `v2`，把 `v3` 視為歷史轉折、`v4` 視為現行 baseline。

## Maintenance Suggestion

如果之後還要繼續往下演化，建議遵守這個原則：

- 不要再把新想法直接堆成 `v4` 裡的額外權重。
- 先明確寫出：
  - 新增的是哪種市場假設
  - 它要解決哪個舊版本的誤判
  - 它會影響事件數、MFE、MAE、bucket 哪一塊
- 如果新想法只是調參，留在 `run_tune_*`。
- 如果新想法改的是事件定義或特徵哲學，再考慮開 `v5` 或抽到模組層。

## Recommended Baseline

目前若要選一個「繼續做長期研究的基準版」：

- 研究回顧看 `v1 -> v4`
- 實際延伸以 `v4` 為基準
- 若要理解轉折點，重點回看 `v2` 與 `v3`

也就是：

- `v1` 是起點
- `v2` 是概念重寫
- `v3` 是研究平台成形
- `v4` 是現階段最完整的 baseline
