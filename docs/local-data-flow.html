StockAnalysis / Local Flow

目前正式的 local data flow

這份頁面只整理目前真正該被視為主線的 3 個部分： OHLC、 warrant dedup、 bs_report rsync + ETL。 其他 crawler 先不列進主流程，避免把 legacy 腳本和正式 pipeline 混在一起。

Flow 01 每日市場行情，直接續抓到 data/ohlc/
Flow 02 權證主檔清單抓取、合併、去重，落到 data/warrant/
Flow 03 從 GCP / local inbox 讀入 bs_report，再增量 ETL 成 parquet

Flow 01 · OHLC

這條線沒有額外 ETL。兩支 crawler 直接看現有檔案最後日期，從下一天補抓到今天為止。

TWSE / TPEX Daily OHLC

Direct append

每個市場各一支 runtime crawler，wrapper 只負責啟動。輸出格式是「每日一個 CSV」，不是每檔股票一個 CSV。

Step 1

Inspect latest date

掃描 data/ohlc/ 下既有的 twse-*.csv / tpex-*.csv，決定續抓起點。

Step 2

Fetch daily market data

TWSE 和 TPEX 各自呼叫官方 API，按日抓回原始表格。

Step 3

Save daily CSV

每個交易日直接落檔成 twse-YYYYMMDD.csv 或 tpex-YYYYMMDD.csv。

Step 4

Consumed by analysis

後續分析程式直接讀這批 CSV，沒有獨立中繼 ETL 層。

Entrypoints apps/twse/crawler-twse-daily-ohlc.py apps/tpex/crawler-tpex-daily-ohlc.py
Runtime src/stockanalysis/runtime/crawlers/twse_daily_ohlc.py src/stockanalysis/runtime/crawlers/tpex_daily_ohlc.py

Flow 02 · Warrant Dedup

這條線的目的不是日常行情，而是維持一份可穩定查表的權證主檔對照清單。

Warrant Master List

Fetch + merge + dedup

抓上市 / 上櫃、已到期 / 未到期四種組合，把本次抓到的資料與既有檔案合併，再依權證代號與權證簡稱去重。

Step 1

Fetch MOPS batches

依 market_type 和 expired_flag 跑四次查詢，下載各批 CSV。

Step 2

Normalize codes

清掉像 ="03002U" 這種 Excel 風格權證代號表示法。

Step 3

Merge with existing file

若 data/warrant/warrant_list_dedup.csv 已存在，先跟舊資料合併。

Step 4

Deduplicate and save

以 權證代號 + 權證簡稱 去重，最後寫回固定檔案位置。

Entrypoint apps/crawlers/Crawler_WarrantList.py
Output data/warrant/warrant_list_dedup.csv

Flow 03 · bs_report Rsync + ETL

這條線是目前最完整的 local pipeline。重點不是 crawler 本身，而是 sync → inbox → incremental parquet → manifest/archive 這個管理層。

bs_report Local Pipeline

Structured ETL

先把 raw 資料同步到 local inbox，再逐日處理資料夾，把每個股票代號增量寫入 parquet，最後用 manifest 控制重跑與 archive。

Step 1

Sync or prepare inbox

可透過 gcloud storage rsync 把 GCP 上的資料同步到 data/bs_report/inbox/。

Step 2

Process daily folders

ETL 逐個讀取 YYYYMMDD/ 資料夾中的 CSV，抽出日期與基本欄位。

Step 3

Incremental parquet write

依股票代號寫入 parquet_twse / parquet_tpex，並以欄位組合去重。

Step 4

Manifest and archive

成功處理後寫入 manifest，並可將已處理資料夾搬到 archive/。

Entrypoint apps/etl/run_bs_report_etl.py --market {twse|tpex|all} [--sync]
Core ETL apps/etl/bs_report_pipeline.py
Inbox Layout data/bs_report/inbox/twse/YYYYMMDD/*.csv data/bs_report/inbox/tpex/YYYYMMDD/*.csv
Outputs data/bs_report/parquet_twse/*.parquet data/bs_report/parquet_tpex/*.parquet data/bs_report/manifests/*.json data/bs_report/archive/*

結論

  • 如果要把 repo 的正式 local pipeline 寫進文件，主體就定義成這 3 條，不要把其他 legacy crawler 混進主線。
  • OHLC 和 warrant dedup 是直接落地型流程；bs_report 則是有明確 ETL 管理層的流程。
  • 後續如果要再整理文件或重構 CLI，最合理的方向是圍繞這 3 條做統一入口。
